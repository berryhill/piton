# Backend integration status

The TypeScript host (`main.ts`, `host.ts`, `backend.ts`, `bridge.ts`) supports a private ACP normalization adapter (`acp-service.ts`) backed by the bounded stdio transport (`acp-runtime.ts`). `runtime-launch.ts` reads private server-owned configuration and verifies the pinned native source manifest. The optional Hermes source patch and exact launch boundary are documented in `runtime/README.md`. Historical retired-Python-backend proofs do not validate this implementation.

Frontend: exact API in CONTRACT.md. Call bootstrap (credentials include), enroll project once via POST /api/chat/projects, then history/conversation. Origin browser sends automatically for POST; GET needs same-origin Fetch Metadata (normal browser fetch). CSRF header for POST. Origin header can be explicitly set only in test client. Project conversation independent of document. Stop is POST /api/chat/stop; interrupted state requires explicit POST /api/chat/recover before next send. Unknown project history returns 403 until enroll.

The host compiles with `pnpm run build:chat` and starts with `pnpm run start:chat`; see RUNNING.md. It requires private state outside static assets and an exact public origin. The ACP service generates a process-only private authorization token; browser input cannot select executable paths, credentials, profile directories or privilege modes. The bridge retains its authenticated, per-project request/receipt contract. Production authentication requires an exact trusted Tailscale login and Serve-to-loopback provenance. Never expose the listener directly or forward untrusted identity headers through another proxy. Anonymous bootstrap is loopback-test-only.

Piton owns durable principal/project-scoped history, explicit recovery, per-turn receipts, request reservation and disconnect cleanup. Hermes child sessions are ephemeral: each turn receives only bounded visible conversation reference data, never the shared profile session database. Unknown adapter sessions after restart require explicit recovery; completed/uncertain user turns are not automatically resent. Model changes invalidate old adapter handles and may require recovery. Stop propagates disconnect cancellation through the private adapter to ACP cancellation and bounded child termination. The browser acknowledgement alone is not termination evidence; acceptance must observe the interrupted run and successful explicit recovery.

Conversation-only runtime policy must enforce empty native/MCP tool surfaces and dispatcher denial; suppress memory, context files, plugins, auxiliary titling and shared-session restoration; reject agentic subprocess provider transports; and preserve these restrictions through model rebuilds and refresh/compaction. `verifyConversationIsolation` remains fail-closed. Activation requires both source identity and actual session-bound policy metadata, not a constant callback or model-list response. Unit tests use inert peers/synthetic local providers; real browser acceptance is separately required at the deployed origin. Live CAD MCP lease/query integration and assistant-to-modeling proposals are not granted by conversation mode and remain separate capabilities.
