# Backend integration status

Current implementation is `backend.ts` with `bridge.ts`, the same-origin `host.ts`, and Node entrypoint `main.ts`. A historical real-model proof used a retired Python backend and does not verify this TypeScript implementation. No current real-model chat integration or live chat deployment is established. Backend HTTP tests exercise a test-only isolation verifier, private bridge, and mock upstream; bridge unit tests also use a mock upstream, and composer tests use mocked fetch. The workstation service serves the isolated manual-modeling test release at commit `d342bb2`, not this chat backend.

Frontend: exact API in CONTRACT.md. Call bootstrap (credentials include), enroll project once via POST /api/chat/projects, then history/conversation. Origin browser sends automatically for POST; GET needs same-origin Fetch Metadata (normal browser fetch). CSRF header for POST. Origin header can be explicitly set only in test client. Project conversation independent of document. Stop is POST /api/chat/stop; interrupted state requires explicit POST /api/chat/recover before next send. Unknown project history returns 403 until enroll.

The host compiles with `pnpm run build:chat` and starts with `pnpm run start:chat`; see RUNNING.md for explicit startup settings and default-denial boundaries. Its options require a private state directory outside static assets and exact public origin; upstream root URL and credential remain server-owned. The backend passes the root upstream URL to the private bridge, which adds `/p/nick-mercer`; the backend's own model probe uses the prefixed API URL. The private bridge binds an ephemeral loopback port and requires that exact port-bearing Host and Origin. Production authentication requires an exact trusted Tailscale login and verified Serve-to-loopback provenance. Never expose the listener directly or allow a different proxy to forward attacker-supplied identity headers. Local bootstrap is permitted only for an isolated loopback origin. The compiled host was exercised in an isolated browser with JSON bootstrap and unavailable-agent status; this is not production or real-model proof.

Project-scoped history, explicit replacement-session recovery, durable per-turn receipts, request reservation, disconnect cleanup and proven-dead Linux lock recovery have source/mock regression coverage. Recovery retains archived evidence and never automatically resubmits an interrupted user turn. Legacy/unknown/PID-reused or boot-mismatched locks and interrupted acquisition/recovery fences fail closed for manual review. Stop reports that upstream cancellation is unconfirmed; closing a transport is not native cancellation proof.

P2 remains incomplete: the context string is bounded/frozen and untrusted, but live browser MCP lease/query integration and assistant-to-modeling proposals are absent. An empty advertised capability list, model listing, prompt, or filtered tool events do not establish runtime isolation. `verifyConversationIsolation` is a server-owned callback: absent, false, or throwing denies availability and conversation before upstream sessions or chat; the bridge rechecks it before each request. Only a genuine independent runtime-policy verifier for the pinned upstream may enable production; the tests' true callback is a mock, not such a verifier. Effective isolation is not implemented or proven here. Production native cancellation and authenticated real-model/browser acceptance remain pending; do not claim a live agent path from these mock tests.
